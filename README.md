1. I think the entire for loop will finish before the Update method ends, rather than running one part of the loop each frame. I think even though the Update runs once per frame, the for loop inside of it will still continue until its condition becomes false. For example, if a loop needs to run 100 times, all 100 repetitions will happen during the same Update call. Therefore, because of this, I think a loop that takes a really long time to finish could make the game lag or even freeze for a moment. So, the game has to wait for the loop to finish before it can continue normally. I learned that we need to be careful about how much work we put inside Update, especially when using loops.
2. When I first tested my game, I noticed that the Cat started falling through the ground after I added the code that allows it to jump through platforms. Before adding that code, the Cat could stand on the ground normally. I realized that the problem was caused by disabling the Cat's Collider whenever it was moving upward. However, my original code did not enable the Collider again when the Cat started falling, so it could pass through the ground instead of landing on it. To fix this, I added an else statement that enables the Collider again when the Cat is no longer moving upward. I also realized that this logic has another weakness because it disables the entire Collider, not just collisions with platforms. This means the Cat could also pass through other solid objects, such as a ceiling, while jumping upward. I think this happens because our code only checks the Cat's vertical movement instead of checking what kind of object it is touching.
